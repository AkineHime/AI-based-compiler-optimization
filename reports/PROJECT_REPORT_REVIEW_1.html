1. Abstract & Problem Motivation

Modern optimizing compilers (e.g., GCC, LLVM) employ predefined, monolithic optimization levels such as -O2 or -O3 that blindly apply fixed pass pipelines across all programs. However, compiler optimizations interact non-linearly: an earlier pass often eliminates structural preconditions for downstream transformations (the Phase-Ordering Problem), and indiscriminately enabling aggressive passes causes substantial performance regressions due to instruction cache thrashing, register spilling, and loop unroll overhead. In our empirical sweep of 270 benchmark programs across all 64 pass combinations, turning all 6 passes on regressed performance on over 243 out of 270 programs compared to the optimal per-program combination.

To solve this, we develop an end-to-end optimizing compiler and machine learning recommendation engine for MiniC—a strongly typed, pointer-free C dialect designed for provably sound transformations. By extracting a 27-dimensional static feature vector from Three-Address Code (TAC) intermediate representation, our risk-aware machine learning model predicts the optimal combination out of 64 pass subsets, achieving a geomean speedup of ×1.23 on unseen held-out programs (capturing 44% of achievable oracle speedup) while keeping compiler regressions strictly under 9%.

3. MiniC Language Specification & Front-End Design

MiniC Design Rationale: Conventional C optimization is constrained by pointer aliasing ambiguities. MiniC omits pointers and dynamic memory allocation (malloc/free), enforcing strict value semantics for multi-dimensional arrays, fixed strings, and nominal structs. This structural guarantee ensures complete alias freedom—every named identifier maps to an isolated memory cell. Transformations like Common Subexpression Elimination and Loop-Invariant Code Motion are provably sound without requiring conservative points-to analysis.

Front-End Pipeline: Implemented in src/minic/frontend/, the front-end tokenizes input using regex lexing and parses via recursive descent following strict BNF grammar rules. Semantic analysis enforces nominal type resolution and array dimensionality. The AST is lowered into Three-Address Code (TAC) in src/minic/ir/, structured into basic blocks with full Control Flow Graph (CFG) edges, dominator trees, and natural loop boundaries.

4. Modular Optimization Passes & Value-Semantics Codegen

The optimization engine (src/minic/optimizer/) implements 6 independently toggleable passes controlled via a 6-bit configuration bitmask ($2^6 = 64$ combinations). Passes run in canonical order (CF → CSE → LU → LICM → SR → DCE) iterated to a fixed point (until no further instruction rewrites occur):

  • Constant Folding & Propagation (CF, Bit 0): Evaluates constant arithmetic/relational subtrees at compile time (e.g. 3 * 5 → 15), eliminates dead branches (ifFalse 1 goto L), and propagates known constants across basic block boundaries.
  • Common Subexpression Elimination (CSE, Bit 1): Applies local value numbering across basic blocks to identify duplicate expressions with identical operand values, reusing existing temporaries.
  • Loop Unrolling (LU, Bit 2): Detects canonical while loops with bounded trip counts, unrolling loop bodies by a factor of 2 or 4 to diminish branch penalties and expose instruction parallelism.
  • Loop-Invariant Code Motion (LICM, Bit 3): Uses dominator trees and natural loop detection to identify instructions whose operands are invariant across loop iterations, hoisting them to loop pre-headers.
  • Strength Reduction (SR, Bit 4): Replaces computationally expensive operations inside loops (e.g., induction variable multiplications i * 8) with low-latency additions (t = t + 8).
  • Dead Code Elimination (DCE, Bit 5): Uses backward liveness analysis to eliminate unused assignments and temporaries that lack downward-exposed uses.
  • Value-Semantics Codegen (src/minic/codegen/): Emits ANSI C code. Arrays and strings are wrapped in single-field structs (typedef struct { int data[10]; } arr_10;), guaranteeing pass-by-value and assignment copy semantics without pointer decay.

5. Static Feature Extraction & Machine Learning Recommender

To recommend the optimal pass configuration without executing or timing the target program, the compiler extracts a 27-dimensional static feature vector directly from the TAC IR and CFG:

Feature Category Dimensions Extracted Compiler Metrics & Significance
Structural Metrics
(src/minic/features/)		 19 Total TAC instructions, basic block count, loop count, max loop nesting depth, branch count, branch density, instruction histograms (arithmetic, multiplication, load, store, call, branch), named vs temp variables, array and struct access counts.
Opportunity Metrics
(src/minic/features/opportunity.py)		 8 Foldable constant expression count, loop-invariant candidate count, common subexpression candidate count, reducible induction multiplication count, unrollable loop count, dead store candidate ratio.

Risk-Aware Recommender Formulation & Abstain-Margin Policy:

Standard regression models that select the pass combo with the highest predicted speedup (argmax) suffer from high regression rates (21% of unseen programs execute slower than unoptimized code due to noisy predictions). We formulated a Risk-Aware Abstain-Margin Policy:

Policy: If maxc ∈ [1..63] S(p, c) ≥ θ (where θ = 1.12×), select c* = argmax S(p, c); else Abstain → Combo 0 (Baseline).

Here, $S(p, c)$ represents the predicted speedup of program $p$ under pass combination $c$, generated by a Histogram Gradient Boosted Tree (HistGBT) regressor. If the expected speedup does not exceed the margin $\theta = 1.12\times$, the compiler safely falls back to Combo 0 (no optimization). This strategy cuts regressions to 9% while retaining 44% of achievable oracle speedup.

GroupKFold Cross-Validation: Cross-validation splits are partitioned strictly by program_id across 5 folds. Because all 64 configurations of a program share identical static features, standard random splits would cause catastrophic feature leakage. GroupKFold ensures rigorous evaluation on unseen code structures.

6. Empirical Benchmark Sweep & Timing Methodology

A comprehensive corpus of 270 benchmark programs was constructed (30 handcrafted algorithms spanning 2D arrays, structs, strings, recursion, numeric loops + 240 parametric synthetic benchmarks). Each program was emitted to C across all 64 pass combinations = 17,280 compiled configurations. Programs were compiled with gcc -O0 (isolating MiniC's optimizer contribution from C compiler passes) and executed 15 times using high-precision wall-clock timing (time.perf_counter()), recording the minimum-interference execution time after 4 warmup runs. Every build verified exit-code equivalence against baseline.
