MiniC  /  compiler optimization  /  measured, not modelled

A restricted C compiler that optimizes, and proves it on the clock

MiniC source is lowered to three-address code, run through five toggleable optimization passes, emitted back to C, and compiled with gcc -O0. Pinning the C compiler at -O0 means every speedup below is the MiniC optimizer’s own work — not gcc’s.

Why a recommender, not just “-O-everything”

No single combo wins

Turning all five passes on is the best choice for only 10 of 30 programs. On the other 20 it leaves speed on the table, and a few strength-reduction-heavy combos make a tight loop up to 11 % slower — the multiply they remove was already cheap under -O0.

A safe fixed default (CSE + LICM, combo 12) never regresses and averages ×1.16. The best fixed combo (CF + DCE + CSE + LICM, combo 15) averages ×1.32. Per-program tuning beats both.

Struct and loop code carries redundant address / field arithmetic and loop-invariant work the passes can lift. Recursion and fixed-string scanning give them almost nothing to remove.

The recommendation model

RandomForest on 19 static features + 5 pass flags

Trained to predict speedup_ratio from features read straight off the AST and TAC — loop nesting, branch density, instruction mix, struct and array access counts — with no timing needed at inference. Cross-validated with GroupKFold keyed on program_id, so whole programs are held out; a program’s 32 rows share identical features and a random split would leak them.
