MiniC  /  compiler optimization  /  measured, not modelled

A restricted C compiler that optimizes, and proves it on the clock

MiniC source is lowered to three-address code, run through six toggleable optimization passes, emitted back to C, and compiled with gcc -O0. Pinning the C compiler at -O0 means every speedup below is the MiniC optimizer’s own work — not gcc’s.

MiniC .mc→ lex / parse / sema→ TAC IR + 27 features→ 6 passes × 64 combos→ TAC → C→ gcc -O0→ timed, min of 15

Struct and loop code carries redundant address / field arithmetic and loop-invariant work the passes can lift. Recursion and fixed-string scanning give them almost nothing to remove.

The recommendation model

Trained to predict speedup_ratio from features read straight off the AST and TAC — loop nesting, branch density, instruction mix, and a static count of how much each pass would transform — with no timing at inference. Cross-validated with GroupKFold on program_id, so whole programs are held out; a program’s 64 rows share identical features and a random split would leak them.
